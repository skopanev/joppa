Read joppa_tree for the workspace types, parents, references, questions and status rules. Use those rules for the current workspace.
Use joppa_objects to find and read current objects. Read one historical revision only when needed. Use joppa_search to find related work.
Read joppa_help with op for the operation you need.
Resolve a copied public ID with joppa_search({"workspace":"...","query":"<ID>"}): the reply gives only that object, with exact_id. Never guess local IDs.

Read an object before you change it. Send its current revision. On an update, send only the data fields that change: data merges by key, and null removes a field. Omit parent and links to keep them. Send clean: true to replace data whole.
Create with save_object and revision:0. Omit id so the server generates it. Preserve the existing id when editing.
Write a title and body that answer the question of the type.
A write takes a public item ID where it takes an address of the workspace. The journal stores the address.
Use joppa_batch for related writes. Retry identical input with the same request_id after a lost response.
Set data.workspace on a node to bind a child workspace; use set_remote_links for links across workspaces.

Create incoming source information as a Note with parent:null. Use structural links to connect it to the objects it informs.
Preserve original source text and language. Record decisions and product inputs in Notes. Keep comments for discussion.
Use a short title. Put context, conditions and evidence in body. Use clean Markdown in authored text.
Show object references as [Title](kind:id), using the title and address you read. Markdown links do not replace structural links.

Check existing Tasks before creating work. Set blocking dependencies explicitly. Read current dependency evidence before changing a revision pin.
A Task is a node like any other: data.assignee names the person or the agent alias, such as lane3, assess marks it ready or waiting, and archive_object ends it. Put the Git commit of finished work in data.commit. Test results prove a criterion. A finished Task does not prove criterion acceptance.
No criterion, no test. A test is a node: save_object with kind test under its criterion (ac or tac), data.title = the test name. Every test in the repository must have a present test node.
Never add or rename a test without its test node in the same change. Archive the test node of a deleted test, and the test nodes of a criterion before the criterion.
joppa_record_results gives "unbound": the test names of the record that have no present test node. A full-run record must give "unbound": [] before a merge.
Use the configured test_results rules. Preserve failures and evidence. Record human decisions only with explicit human instruction.

Prefer English for new technical text. Preserve existing text and quotations in their original language. Apply the writing rules below.
Keep code reviews, diffs and execution logs in Git or the agent bus. Use the MCP client's existing OAuth login.
When several agents share one account, send your agent name as alias on each tool call, for example "alias": "p1". The journal keeps it next to the account.
