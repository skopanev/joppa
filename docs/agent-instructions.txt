Read joppa_tree for the types, parents, references, questions, status rules and typed fields of the workspace. Use those rules.
A typed field (fields.<name>) has type, values and from. The order of values is the rollup priority: the first value wins. from own: the node stores the value. from children, links or parent: the server computes it, a read gives it in data, and a save that sends it is refused.

Reads:
- joppa_objects reads a public item ID, such as joppa-R-DP6KXM62, as an address. Send it as address.
- Read many objects in one call. Send 2 to 25 addresses "a,b,c" with fields, or parent with depth and fields, for example {"parent":"requirement:r","depth":2,"fields":["title","body","status"]}. Do not read one object for each call in a loop.
- fields keeps the named keys on a list and on an address read.
- Each list gives items, total and next_cursor, with at most 25 items in a page. Send next_cursor as cursor to read the next page.
- To count nodes, send count: true or group_by (1 to 3 keys) to joppa_objects. Do not page through a list to count it.
- Use joppa_search to find related work by words. Read one historical revision only when needed.
- Read joppa_help with op for the fields of one operation, with section process for the work rules and with section writing for the text rules.

Writes:
- Read an object before you change it. Send its current revision. On an update, send only the data fields that change: data merges by key, and null removes a field. Omit parent and relations to keep them. A sent relation key replaces its edges, and null removes it. Send clean: true to replace data whole.
- Create with save_object and revision 0. Omit id so the server generates it. Keep the id when you edit.
- The write reply gives the new revision. Send it with the next write of that object.
- Link objects with the relations map of save_object, not with text. Add findings as comments with op note.
- Write a title and body that answer the question of the type.
- A write takes a public item ID where it takes an address. The journal stores the address.
- Use joppa_batch for related writes. Retry identical input with the same request_id after a lost response.
- Each data value holds at most the field_max_length of its type. Over 1 kb: prefer attach as a file.
- Set data.workspace on a node to bind a child workspace. Use set_remote_links for links across workspaces.
- Never overwrite or remove Evidence, failures or test results. Record human decisions only with explicit human instruction.

Session:
- alias: when several agents share one account, send your agent name as alias on each tool call, for example "alias": "p1". The journal shows it next to the actor.
- Use the MCP client's existing OAuth login.
- An HTTP 503 answer with Retry-After: 30 and JSON-RPC error -32000 means maintenance, such as a deploy. Wait 30 seconds and retry the same call with the same request_id.
- Prefer English for new technical text. Keep existing text and quotations in their original language.
